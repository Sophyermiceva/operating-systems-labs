\section{Purpose of the Work}
The purpose of this laboratory work is to develop practical Bash command-line skills and understand command lookup, shell expansion, quoting, redirection, chaining, jobs, pipelines, text filters, and a first reusable shell script. A synthetic \texttt{access.log} with 500 records was used for the text-processing tasks.

\section{Part 1. Move Fast, Find Help}
\begin{lstlisting}
cd is a shell builtin
ls is aliased to `ls --color=auto'
echo is a shell builtin
/usr/bin/ls
nosuchprog: command not found
exit code: 127
\end{lstlisting}
\figcap{Figure 1.1 -- Actual command-type and missing-command output}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item \texttt{cd} and \texttt{echo} are shell built-ins. \texttt{ls} is an alias that ultimately invokes \texttt{/usr/bin/ls}. \texttt{cd} must be a built-in because only the current shell can change its own working directory.
\item The inspected PATH contained 49 directories, and the external \texttt{ls} executable was in \texttt{/usr/bin}.
\item A missing command returned exit status 127.
\item The \texttt{ls} option for sorting by modification time is \texttt{-t}; newer files are listed first by default.
\end{enumerate}

\section{Part 2. What the Shell Does to the Command Line}
\begin{lstlisting}
a.c b.c
file1.txt file2.txt
a.c alfa beta.txt b.c
*.xyz
ls: cannot access 'alfa': No such file or directory
ls: cannot access 'beta.txt': No such file or directory
'alfa beta.txt'
$HOME /home/sofia $HOME
1 2 3 4 5
42
today is Monday, I am sofia
log1.txt  log2.txt  log3.txt
\end{lstlisting}
\figcap{Figure 2.1 -- Actual results of globbing, quoting and expansion experiments}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item Bash transforms many command lines before the selected program starts.
\item \texttt{echo} does not search the filesystem for \texttt{*.c}; Bash performs pathname expansion and passes the resulting names to \texttt{echo}.
\item \texttt{ls alfa beta.txt} produces two arguments. Valid fixes are \texttt{ls "alfa beta.txt"} and \texttt{ls alfa\textbackslash\ beta.txt}.
\item Single quotes preserve text literally, double quotes preserve spaces while allowing expansions, and a backslash escapes an individual special character.
\end{enumerate}

\section{Part 3. Redirection, Chaining and Jobs}
\begin{lstlisting}
$ ls /etc /nope > out.txt 2> err.txt
$ wc -l out.txt
184 out.txt
$ cat err.txt
ls: cannot access '/nope': No such file or directory
\end{lstlisting}
\figcap{Figure 3.1 -- Actual stdout and stderr redirection result}

\begin{lstlisting}
[1] 2384
[1]+  Running                 sleep 100 &
[1]+  Terminated              sleep 100
\end{lstlisting}
\figcap{Figure 3.2 -- Actual background-job and termination output}

The operators have different control-flow meanings: \texttt{;} always continues, \texttt{\&\&} continues only after success, and \texttt{||} continues only after failure. The order of \texttt{> all.txt 2>\&1} and \texttt{2>\&1 > all.txt} matters because descriptor duplication uses the destination that exists at the moment the duplication is performed.

\section{Part 4. Answering Questions with One-Liners}
\begin{lstlisting}
100
/page0
/page1
/page2
/page3
Count: 4
125 /page3
125 /page2
125 /page1
125 /page0
15 user5
15 user3
Total: 72
Failed: 15
10:10 user0
10:15 user5
10:20 user3
\end{lstlisting}
\figcap{Figure 4.1 -- Actual main results produced by oneliners.sh}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item There were 100 failed requests.
\item Four pages were requested: \texttt{/page0} through \texttt{/page3}.
\item Each page received 125 requests, giving a total of 500.
\item \texttt{user3} and \texttt{user5} had the maximum number of failed requests, 15 each.
\item \texttt{user3} made 72 requests, of which 15 failed.
\item The last three failed requests were \texttt{10:10 user0}, \texttt{10:15 user5}, and \texttt{10:20 user3}.
\item The inspected login-shell counts were 26 \texttt{/usr/sbin/nologin}, 2 \texttt{/bin/bash}, 1 \texttt{/bin/sync}, and 1 \texttt{/bin/false}.
\item \texttt{ls -l /etc | wc -l} was one line larger than \texttt{ls /etc | wc -l} because long-format \texttt{ls} adds a \texttt{total} summary line.
\end{enumerate}

\section{Part 5. First Shell Script}
\begin{lstlisting}
500 requests, 100 failed
user0: 14 failures
user1: 14 failures
user2: 14 failures
user3: 15 failures
user4: 14 failures
user5: 15 failures
user6: 14 failures
\end{lstlisting}
\figcap{Figure 5.1 -- Actual report.sh output for access.log}

\begin{lstlisting}
no such file: nope.log
exit code: 1
\end{lstlisting}
\figcap{Figure 5.2 -- Actual report.sh error handling for a missing file}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item \texttt{\#!/bin/bash} is the shebang that selects Bash when the script is executed directly.
\item \texttt{./report.sh} explicitly names the current directory because \texttt{.} is normally not included in PATH.
\item \texttt{>\&2} sends diagnostics to standard error, and \texttt{exit 1} makes failure detectable by the caller.
\end{enumerate}

\section{Conclusion}
The laboratory showed that Bash performs command discovery, expansion, quoting, substitution and redirection before a target program runs. Pipelines and small text-processing utilities can be composed to analyze structured data, and the final script combined these mechanisms with variables, conditionals, loops, stderr handling and exit statuses.
