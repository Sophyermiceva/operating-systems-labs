\section{Purpose of the Work}
The purpose of this laboratory work is to compare the xv6 shell with Bash, adapt a small program to the current xv6 API, inspect argument handling, and connect the observed behavior with the implementation in \texttt{user/sh.c}.

\section{Part 1. Fixing and Testing sleep}
\begin{lstlisting}
25:int pause(int);
\end{lstlisting}
\figcap{Figure 1.1 -- Actual current xv6 user API entry for pause}

The current xv6 tree uses \texttt{pause(int)} rather than the older \texttt{sleep(int)} system call. The repository version of \texttt{user/sleep.c} therefore calls \texttt{pause(atoi(argv[1]))}.

\begin{lstlisting}
$ sleep 20
$ sleep
usage: sleep <ticks>
\end{lstlisting}
\figcap{Figure 1.2 -- Actual sleep tests in xv6}

\subsection{Observation}
With one argument the program waits for the requested number of ticks. With a missing argument it prints the usage message and exits with an error.

\section{Part 2. Bash versus the xv6 Shell}
\begin{lstlisting}
$ echo hello > f ; cat < f
hello
$ ls | grep READ
README         2 2 2441
$ (echo a; echo b) | wc
2 2 4
$ echo one ; echo two
one
two
$ echo bg &
bg
$ ls *
ls: cannot open *
$ echo $HOME
$HOME
$ echo "a b"
"a b"
\end{lstlisting}
\figcap{Figure 2.1 -- Actual selected xv6-shell results}

\begin{lstlisting}
$ cd d
$ ls
exec ls failed
\end{lstlisting}
\figcap{Figure 2.2 -- Actual failure of PATH-style command lookup after cd in xv6}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item Both shells support normal program execution, redirection, pipes, lists, grouped commands and background execution. Bash additionally provides globbing, variable expansion, quote processing, PATH lookup, history, completion and richer job control.
\item After \texttt{cd d}, xv6 cannot find \texttt{ls} by name because it does not search PATH. The executable can be addressed explicitly from the parent directory.
\item PATH lookup would be one of the more straightforward conveniences to add; full Bash-like quoting and expansion would require substantially more parser logic.
\end{enumerate}

\section{Part 3. Who Expands *? Inspecting argc and argv}
\begin{lstlisting}
$ ./args one two three
argc = 4
argv[0] = [./args]
argv[1] = [one]
argv[2] = [two]
argv[3] = [three]

$ ./args *.c "x y"
argc = 5
argv[0] = [./args]
argv[1] = [args_linux.c]
argv[2] = [one.c]
argv[3] = [two.c]
argv[4] = [x y]
\end{lstlisting}
\figcap{Figure 3.1 -- Actual argv produced through Bash}

\begin{lstlisting}
$ args *.c "x y"
argc = 4
argv[0] = [args]
argv[1] = [*.c]
argv[2] = ["x]
argv[3] = [y"]

$ args $HOME
argc = 2
argv[0] = [args]
argv[1] = [$HOME]
\end{lstlisting}
\figcap{Figure 3.2 -- Actual argv produced through the xv6 shell}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item Bash produced five arguments for \texttt{*.c "x y"}: program name, three expanded filenames, and one quoted argument. xv6 produced four: program name, literal \texttt{*.c}, and two words containing the quote characters.
\item The shell, not the target program or kernel, constructs the argument vector. Bash performs the expansions; xv6 performs far fewer transformations.
\item Repeated spaces do not produce empty arguments because both shells tokenize on whitespace.
\end{enumerate}

\section{Part 4. Reading the xv6 Shell Source}
\begin{lstlisting}
8:#define EXEC  1
9:#define REDIR 2
10:#define PIPE  3
11:#define LIST  4
12:#define BACK  5
14:#define MAXARGS 10
\end{lstlisting}
\figcap{Figure 4.1 -- Actual command kinds found in user/sh.c}

\begin{lstlisting}
75:  case EXEC:
83:  case REDIR:
93:  case LIST:
101:  case PIPE:
125:  case BACK:
\end{lstlisting}
\figcap{Figure 4.2 -- Actual execution switch locations in user/sh.c}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item The five command kinds are \texttt{EXEC}, \texttt{REDIR}, \texttt{PIPE}, \texttt{LIST}, and \texttt{BACK}. Parentheses group a command but do not create a sixth command type.
\item \texttt{cd} is handled by the shell's main process because changing directory in a child would not change the parent shell's working directory.
\item There is no Bash-style globbing or variable-substitution implementation in \texttt{sh.c}, which explains the literal \texttt{*} and \texttt{\$HOME} behavior.
\end{enumerate}

\section{Conclusion}
The comparison showed that xv6 implements the core Unix shell model but intentionally omits many interactive and expansion features provided by Bash. Printing \texttt{argv} demonstrated that most apparent ``command'' behavior is actually shell preprocessing performed before \texttt{exec()}.
