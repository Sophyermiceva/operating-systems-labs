\section{Purpose of the Work}
The purpose of this laboratory work is to explore Linux filesystem concepts through direct experiments: file types, inodes, hard and symbolic links, permissions, special permission bits, disk usage, block devices, and the \texttt{/proc} pseudo-filesystem.

\section{Part 1. The Tree and File Types}
\begin{lstlisting}
$ ls -ld /etc /etc/passwd /bin /dev/null /tmp
lrwxrwxrwx  1 root root     7 Apr 22  2024 /bin -> usr/bin
crw-rw-rw-  1 root root  1, 3 Oct  9 02:09 /dev/null
drwxr-xr-x 98 root root  4096 Oct 12 15:40 /etc
-rw-r--r--  1 root root  1545 May  2  2025 /etc/passwd
drwxrwxrwt 13 root root 12288 Oct 12 15:35 /tmp
\end{lstlisting}
\figcap{Figure 1.1 -- Actual file types and permissions reported by ls -ld}

\begin{lstlisting}
$ du -sh /var/log 2>/dev/null
392M    /var/log
$ du -sh /usr 2>/dev/null
7.4G    /usr
\end{lstlisting}
\figcap{Figure 1.2 -- Actual disk-usage comparison of /var/log and /usr}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item The first character of \texttt{ls -l} identifies the object type: directory \texttt{d}, regular file \texttt{-}, symbolic link \texttt{l}, and character device \texttt{c}.
\item On this system \texttt{/bin} is a symbolic link to \texttt{usr/bin}.
\item \texttt{/dev/null} is a character device. \texttt{/dev/sdc} is a block device containing the root filesystem.
\item \texttt{/usr} was approximately 7.4 GB compared with 392 MB for \texttt{/var/log}, roughly nineteen times larger.
\end{enumerate}

\section{Part 2. Inodes and Links}
\begin{lstlisting}
$ stat notes.txt
File: notes.txt
Size: 6               Blocks: 8          IO Block: 4096   regular file
Device: 8,32    Inode: 44076       Links: 1
Access: (0644/-rw-r--r--)  Uid: (1000/sofia)  Gid: (1000/sofia)
\end{lstlisting}
\figcap{Figure 2.1 -- Actual inode metadata of notes.txt}

\begin{lstlisting}
$ ln notes.txt hard.txt
$ ls -li notes.txt hard.txt
44076 -rw-r--r-- 2 sofia sofia 6 Oct 12 15:42 hard.txt
44076 -rw-r--r-- 2 sofia sofia 6 Oct 12 15:42 notes.txt
$ rm notes.txt
$ cat hard.txt
hello
\end{lstlisting}
\figcap{Figure 2.2 -- Actual hard-link experiment}

\begin{lstlisting}
$ ln -s hard.txt soft.txt
$ ls -li hard.txt soft.txt
44076 -rw-r--r-- 1 sofia sofia 6 Oct 12 15:42 hard.txt
44078 lrwxrwxrwx 1 sofia sofia 8 Oct 12 15:43 soft.txt -> hard.txt
$ rm hard.txt
$ cat soft.txt
cat: soft.txt: No such file or directory
\end{lstlisting}
\figcap{Figure 2.3 -- Actual symbolic-link experiment}

\begin{lstlisting}
$ echo x > one.txt
$ ls -l one.txt
-rw-r--r-- 1 sofia sofia 2 Oct 12 15:43 one.txt
$ du -h one.txt
4.0K    one.txt
$ truncate -s 1G big.img
$ ls -lh big.img
-rw-r--r-- 1 sofia sofia 1.0G Oct 12 15:43 big.img
$ du -h big.img
0       big.img
\end{lstlisting}
\figcap{Figure 2.4 -- Actual logical-size and sparse-file experiment}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item \texttt{Inode: 44076} is the inode number; \texttt{Links: 1} is the number of hard-link directory entries referring to it.
\item Removing one hard-link name does not remove the data while another hard link still references the inode.
\item A symbolic link has its own inode and stores a pathname. After removing its target it becomes broken. Its size was 8 bytes because \texttt{hard.txt} has eight characters.
\item A new directory has link count 2; each subdirectory increases the parent's link count through its \texttt{..} entry.
\item Logical size and allocated space differ. The small file occupied one filesystem block, while the 1 GB sparse file initially occupied no data blocks.
\end{enumerate}

\section{Part 3. Permissions}
\begin{lstlisting}
$ echo secret > s.txt
$ chmod 600 s.txt
$ ls -l s.txt
-rw------- 1 sofia sofia 7 Oct 12 15:47 s.txt
$ chmod 000 s.txt
$ cat s.txt
cat: s.txt: Permission denied
$ chmod u+r s.txt
$ cat s.txt
secret
\end{lstlisting}
\figcap{Figure 3.1 -- Actual regular-file permission experiment}

\begin{lstlisting}
$ chmod u=r,go= box
$ ls box
ls: cannot access 'box/f': Permission denied
f
$ cat box/f
cat: box/f: Permission denied
$ chmod u=x,go= box
$ ls box
ls: cannot open directory 'box': Permission denied
$ cat box/f
hi
\end{lstlisting}
\figcap{Figure 3.2 -- Actual directory read-versus-execute permission experiment}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item Common modes include \texttt{600}, \texttt{644}, \texttt{755}, and \texttt{700}, combining owner/group/other read, write and execute permissions.
\item File ownership does not bypass ordinary permission bits; mode \texttt{000} prevented the normal owner process from reading the file.
\item With umask \texttt{0022}, new files derived from 666 became 644 and new directories derived from 777 became 755.
\item Directory read permission allows listing names, while execute permission allows pathname traversal and access to a known entry.
\item The setuid bit on \texttt{/usr/bin/passwd} allows controlled privileged updates, while the sticky bit on \texttt{/tmp} protects other users' files in the shared writable directory.
\end{enumerate}

\section{Part 4. Disks and the Kernel as Files}
\begin{lstlisting}
NAME MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda    8:0    0 388.4M  1 disk
sdb    8:16   0     4G  0 disk [SWAP]
sdc    8:32   0     1T  0 disk /mnt/wslg/distro
                               /
\end{lstlisting}
\figcap{Figure 4.1 -- Actual block devices reported by lsblk}

\begin{lstlisting}
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdc       1007G   22G  934G   3% /
\end{lstlisting}
\figcap{Figure 4.2 -- Actual root-filesystem usage}

\begin{lstlisting}
$ grep -c processor /proc/cpuinfo
16
$ head -3 /proc/meminfo
MemTotal:       14186832 kB
MemFree:        13273344 kB
MemAvailable:   13354732 kB
\end{lstlisting}
\figcap{Figure 4.3 -- Actual CPU and memory information read through /proc}

\subsection{Observe answers}
\begin{enumerate}[label=\arabic*.]
\item The WSL2 root filesystem is on \texttt{/dev/sdc}, mounted as ext4; \texttt{/dev/sdb} provides 4 GB of swap.
\item The root filesystem had a size of approximately 1007 GB, with 22 GB used and 934 GB available.
\item The environment exposed 16 logical processors and 14,186,832 kB of RAM (about 13.5 GiB).
\item \texttt{/proc/self} refers to the process that accesses it; therefore \texttt{head -5 /proc/self/status} reports information about \texttt{head} itself.
\end{enumerate}

\section{Conclusion}
The experiments connected user-visible filesystem behavior with inodes, links, permission bits, allocated blocks, devices and process/kernel information. They also demonstrated the distinction between names and inodes, between logical and allocated size, and between directory read and execute permissions.
